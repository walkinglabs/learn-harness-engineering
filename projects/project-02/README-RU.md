# Проект 02: Рабочее пространство, читаемое агентом

Продемонстрируйте, как читаемость репозитория и явные артефакты снижают потерю контекста при разработке в несколько сессий.

## Структура каталогов

| Каталог     | Значение                                                                                                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `starter/`  | **Отправная точка**: основан на solution из project-01, импорт документов, детальный просмотр и персистентность ещё предстоит реализовать. Харнесс слабый: AGENTS.md минимален, передачи между сессиями нет. |
| `solution/` | **Эталонная реализация**: все новые функции реализованы, с полной документацией рабочего пространства (ARCHITECTURE.md, PRODUCT.md, session-handoff.md).                                                     |

## Как использовать

```sh
# Требуется минимум 2 сессии агента для завершения
cd starter
npm install
# Сессия A: реализуйте импорт документов и детальный просмотр
# Сессия B: реализуйте персистентность (наблюдайте, быстро ли агент восстанавливает контекст)

cd ../solution
npm install
# Повторите с полным харнессом и сравните скорость восстановления сессии
```

## Точный контракт задачи

Начните со `starter/`. Starter уже содержит оболочку Project 01 и минимальный
харнесс. Задача — добавить продуктовый срез Project 02 и документацию
рабочего пространства, которая позволит второй сессии быстро восстановиться.

| Функция / артефакт         | Состояние в starter                                                           | Свидетельства в solution                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Импорт документов          | Поток импорта не завершён в renderer, preload, IPC и `DocumentService`        | `src/renderer/components/ImportPanel.tsx`, `src/main/ipc-handlers.ts`, `src/services/document-service.ts` |
| Детали документа           | Панель деталей не загружает и не отображает полное содержимое файла через IPC | `src/renderer/components/DocumentDetail.tsx`, `IPC_CHANNELS.GET_DOCUMENT_CONTENT`                         |
| Базовая персистентность    | Импортированные документы не полностью восстанавливаются после перезапуска    | `src/services/persistence-service.ts`, обработка `documents-meta.json`                                    |
| Читаемое агентом состояние | В starter нет итогового файла передачи                                        | `session-handoff.md`, расширенный `docs/ARCHITECTURE.md`, расширенный `docs/PRODUCT.md`                   |

Выполняйте это как упражнение из двух сессий. Остановите Сессию A до того, как все три
продуктовые функции будут завершены, затем начните Сессию B только из состояния
репозитория. Главное сравнение — насколько быстрее Сессия B может возобновить работу,
когда существуют `session-handoff.md` и документация.

## Реализуемые функции

- Поток импорта документов (выбор файла плюс передача через IPC)
- Детальный просмотр документа (метаданные плюс отображение содержимого)
- Базовая персистентность (импортированные документы сохраняются после перезапуска)
