# Проект 01: Базовый vs минимальный харнесс

Сравните, как слабый харнесс (только промпт) и явный харнесс (файлы правил плюс механизмы верификации) влияют на процент завершения задач у AI-агента-программиста.

## Структура каталогов

| Каталог     | Значение                                                                                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `starter/`  | **Отправная точка**: только расплывчатый `task-prompt.md`, без AGENTS.md и без feature_list.json. Это версия «слабого харнесса», которую вы даёте агенту.                       |
| `solution/` | **Эталонная реализация**: тот же код приложения, но с полным набором файлов харнесса (AGENTS.md, feature_list.json, init.sh, claude-progress.md). Это версия «явного харнесса». |

## Как использовать

```sh
# 1. Запустите задачу для агента один раз со starter (слабый харнесс)
cd starter
npm install
# Передайте содержимое task-prompt.md в качестве промпта для Claude Code / Codex
# Попросите агента реализовать: запуск окна, список документов, панель вопросов и ответов, каталог данных
# Не давайте агенту файлы solution во время этого запуска.

# 2. Запустите ту же задачу с solution (явный харнесс)
cd ../solution
npm install
# Попросите агента прочитать AGENTS.md, init.sh, feature_list.json и claude-progress.md
# перед тем, как трогать код. Код продукта уже должен удовлетворять тем же четырём функциям.

# 3. Сравните два результата
# - Была ли задача выполнена?
# - Сколько потребовалось повторных попыток?
# - Заявлял ли агент «готово» слишком рано?
```

## Точный контракт задачи

Промпт в starter намеренно расплывчатый (`starter/task-prompt.md` содержит только
«Build an Electron app that can show documents and answer questions.» — «Создайте
Electron-приложение, которое может показывать документы и отвечать на вопросы»). Используйте харнесс
solution, чтобы превратить этот расплывчатый запрос в конкретный:

| Функция                  | Свидетельства в starter для проверки         | Свидетельства в solution для сравнения         |
| ------------------------ | -------------------------------------------- | ---------------------------------------------- |
| Запуск окна              | `src/main/main.ts`, `src/preload/preload.ts` | элемент `window-launch` в `feature_list.json`  |
| Панель списка документов | `src/renderer/components/DocumentList.tsx`   | элемент `document-list` в `feature_list.json`  |
| Панель вопросов          | `src/renderer/components/QuestionPanel.tsx`  | элемент `question-panel` в `feature_list.json` |
| Каталог данных           | `src/services/persistence-service.ts`        | элемент `data-directory` в `feature_list.json` |

Этот проект — эксперимент, а не обычное задание «дополните starter до состояния
solution». Учебный результат — измеренная разница между запуском только с промптом
и запуском, который начинается с явных правил репозитория и артефактов верификации.

## Реализуемые функции

- Electron-окно успешно запускается
- В UI отображается область списка документов
- В UI отображается панель вопросов и ответов
- Приложение создаёт и использует локальный каталог данных
