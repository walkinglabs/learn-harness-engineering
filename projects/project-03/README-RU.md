# Проект 03: Многосессионная непрерывность с контролем области работ

Оцените, улучшают ли логи прогресса, передача между сессиями, явный контроль
области работ и контрольные точки верификации, точность выполнения задач при перезапусках.

## Структура каталогов

| Каталог     | Значение                                                                                                                                                                                                                                                                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `starter/`  | **Отправная точка**: основан на solution из project-02, разбиение документов на чанки, извлечение метаданных, статус индексации и обоснованные ответы (grounded QA) ещё предстоит реализовать. Есть начальный `feature_list.json`, но нет полного харнесса перезапуска (`init.sh`, `session-handoff.md`, `claude-progress.md`, чек-лист чистого состояния). |
| `solution/` | **Эталонная реализация**: все функции реализованы. AGENTS.md включает стратегию «по одной функции за раз», а репозиторий дополнен артефактами перезапуска/непрерывности (`init.sh`, `session-handoff.md`, `claude-progress.md`, `clean-state-checklist.md`).                                                                                                |

## Как использовать

```sh
cd starter
npm install
# Запустите минимум две сессии агента. Остановитесь один раз в середине задачи, затем возобновите работу из состояния репозитория.
# Понаблюдайте, сохраняет ли агент область работ и обновляет ли feature_list.json.

cd ../solution
npm install
# Изучите завершённые артефакты непрерывности и свидетельства реализации функций.
```

## Точный контракт задачи

Starter Project 03 — это не пустое приложение. Это Project 02 плюс незавершённая
работа по индексации и обоснованным ответам. Выполняйте эти пункты по одному:

| Функция / артефакт                 | Состояние в starter                                                                     | Свидетельства в solution                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Разбиение документов на чанки      | `IndexingService` нуждается в создании чанков с учётом абзацев                          | `src/services/indexing-service.ts`, элемент `document-chunking` в `feature_list.json`   |
| Извлечение метаданных              | Метаданные документа неполны для работы индексации                                      | `src/services/document-service.ts`, `DocumentDetail.tsx`, элемент `metadata-extraction` |
| UI статуса индексации              | Строке статуса нужны количество проиндексированных / общее число чанков / цвета статуса | `src/renderer/components/StatusBar.tsx`, `App.tsx`, элемент `indexing-status-ui`        |
| Обоснованные ответы (Grounded Q&A) | QA должен цитировать извлечённые чанки с фрагментами и уровнем уверенности              | `src/services/qa-service.ts`, `QuestionPanel.tsx`, элемент `grounded-qa`                |
| Харнесс непрерывности              | В starter нет итоговых артефактов перезапуска/передачи                                  | `init.sh`, `session-handoff.md`, `claude-progress.md`, `clean-state-checklist.md`       |

Не воспринимайте это как «добавьте любую многосессионную функцию». Задуманный
продуктовый срез — это индексация плюс QA на основе цитирования, а задуманный
срез харнесса — отслеживание прогресса с возможностью перезапуска.

## Реализуемые функции

- Разбиение документов на чанки (с учётом абзацев, около 500 символов)
- Извлечение метаданных (количество слов, строк, абзацев)
- Статус индексации отображается в UI
- Базовый поток QA с цитированием источников
