# Проект 06: Наблюдаемость и отладка во время выполнения (итоговый проект)

Итоговый проект: постройте и протестируйте полный харнесс, затем запустите циклы
очистки, чтобы проверить качество и поддерживаемость.

## Структура каталогов

| Каталог     | Значение                                                                                                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `starter/`  | **Отправная точка**: полный код продукта, но харнесс намеренно ослаблен (только базовый AGENTS.md, без feature_list.json, передачи между сессиями или чек-листа чистого состояния). |
| `solution/` | **Эталонная реализация**: максимальный харнесс, со всеми файлами артефактов, высокими оценками в документе качества, скриптами бенчмарков и сканерами очистки.                      |

## Как использовать

```sh
cd starter
npm install
# Запустите приложение и вручную зафиксируйте поведение при слабом харнессе.
# Starter намеренно не включает benchmark.sh или cleanup-scanner.sh.

cd ../solution
npm install
# Запустите тот же бенчмарк с полным харнессом
# Выполните циклы очистки
# Сравните изменения оценок в quality-document.md

# Запустить тесты бенчмарка
./scripts/benchmark.sh

# Запустить сканирование очистки
./scripts/cleanup-scanner.sh
```

## Точный контракт задачи

Project 06 — это итоговое сравнение между полным продуктом со слабой поверхностью
харнесса и тем же продуктом, усиленным полным набором артефактов харнесса. В отличие
от предыдущих проектов, starter уже содержит большую часть функциональности продукта.
Разрыв — в операционной системе вокруг кода.

| Область                 | Состояние в starter                                                                                     | Свидетельства в solution                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Поведение продукта      | Импорт, индексация, QA, история, обратная связь, сброс в основном существуют                            | Те же функции плюс более строгая валидация и доказательства персистентности                                |
| Файлы харнесса          | Базовый `AGENTS.md`, нет `feature_list.json`, нет `session-handoff.md`, нет чек-листа чистого состояния | `AGENTS.md`, `CLAUDE.md`, `feature_list.json`, `init.sh`, `session-handoff.md`, `clean-state-checklist.md` |
| Отслеживание качества   | Только начальный `quality-document.md`                                                                  | `quality-document.md` с более высокими оценками, `evaluator-rubric.md`                                     |
| Бенчмаркинг             | Нет скриптов бенчмарка или очистки                                                                      | `scripts/benchmark.sh`, `scripts/cleanup-scanner.sh`, `scripts/check-architecture.sh`                      |
| Документация надёжности | Минимальная документация                                                                                | `docs/ARCHITECTURE.md`, `docs/PRODUCT.md`, `docs/RELIABILITY.md`                                           |

Не ожидайте, что starter содержит команды бенчмарка, показанные для solution. Для
запуска со слабым харнессом фиксируйте базовые наблюдения вручную; для запуска
solution используйте готовые скрипты бенчмарка и очистки.

## Реализуемые функции

- Импорт документов
- Построение или обновление индекса
- Ответы на вопросы с цитированием
- Обратная связь во время выполнения
- Читаемое, перезапускаемое состояние репозитория
