# Проект 04: Обратная связь во время выполнения и структурный контроль

Внедрите наблюдаемость во время выполнения и проверки структурных границ,
одновременно отлаживая заранее внедрённый дефект времени выполнения.

## Структура каталогов

| Каталог | Значение |
|------|------|
| `starter/` | **Отправная точка**: основан на solution из project-03, логирование и функции структурных границ ещё предстоит реализовать. В `IndexingService` есть скрытый заранее внедрённый баг: файлы длиннее 1000 символов могут порождать пустые чанки. Нет скрипта проверки архитектуры и итогового чек-листа чистого состояния. |
| `solution/` | **Эталонная реализация**: модуль структурированного логирования, скрипт проверки архитектурных границ, заранее внедрённый баг исправлен. |

## Как использовать

```sh
cd starter
npm install
# 1. Понаблюдайте, может ли агент обнаружить баг через логи
# 2. Импортируйте большой файл и проверьте, корректно ли ведёт себя разбиение на чанки

cd ../solution
npm install
# Сравните, насколько структурированные логи ускоряют диагностику
```

## Точный контракт задачи

Project 04 — это упражнение на отладку и защитные механизмы. Starter уже содержит
продуктовый срез Project 03, но время выполнения сложнее анализировать, а
заранее внедрённый дефект разбиения на чанки следует исправлять только после того,
как агент сможет увидеть достаточно доказательств.

| Функция / артефакт | Состояние в starter | Свидетельства в solution |
|------|------|------|
| Структурированное логирование | Нет общего сервиса логгера | `src/services/logger.ts`, вызовы логирования в `main.ts`, `ipc-handlers.ts` и сервисах |
| Диагностика импорта / индексации | Сбои трудно отследить по выводу во время выполнения | Записи логов вокруг импорта, начала/завершения индексации и путей сбоя QA |
| Архитектурные границы | Нет скрипта, проверяющего расхождение границ renderer/main/service | `scripts/check-architecture.sh`, `docs/ARCHITECTURE.md`, правила границ в AGENTS |
| Заранее внедрённый баг разбиения на чанки | Большие файлы могут порождать некорректный/пустой вывод чанков | Исправленная логика абзацев/чанков в `src/services/indexing-service.ts` |
| Чистая передача | В starter нет итогового чек-листа | `clean-state-checklist.md` |

Используйте длинный образец документа, чтобы воспроизвести баг до и после исправления.
Успешное решение должно демонстрировать как изменения кода, так и диагностические
доказательства, а не просто заявление об успехе.

## Реализуемые функции

- Логи запуска
- Логи импорта и индексации
- Видимый путь сбоя QA
- Явные границы между слоями main, preload, renderer и services
- Отладка заранее внедрённого дефекта времени выполнения
